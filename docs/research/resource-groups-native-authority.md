# Native resource-group authority: non-renamability narrows the race, but does not grant delegation

**Status:** 2026-11-05 — source/public-document review and an unactivated descriptor-relative child-writer prototype; no native host, unit, cgroup, or placement operation was run. This is **not** evidence of supported mapped execution.

The [accepted design](../design/resource-groups.md#2-ownership-and-placement-architecture) permits only verified existing user-manager delegation or an authorized manager-owned child route. The [plan](../design/resource-groups-plan.md#brief-3--least-authority-linux-adapter-unactivated-descriptor-relative-prototype-writerplacement-remain-unbuilt) correctly refuses the real writer, while its fake admission algorithm tests conditional sequencing. Its reason for *stable-name* refusal needs narrowing: the generic-directory rename attack does not establish that rename is possible on a unified cgroup hierarchy.

## The exact failure and what the new evidence changes

At this tree, [`ReconcileUserIO`](../../internal/resourcegroups/authority_linux.go#L23-L32) pins a cgroup-v2 directory, then always refuses. The injected [`ReconcileDelegatedIOAndStart`](../../internal/resourcegroups/authority_linux.go#L43-L59) uses pathname callbacks; no production caller supplies a native write or PID observation. The unactivated [`pinnedIOChildren`](../../internal/resourcegroups/pinnedio_linux.go) prototype opens the assigned group and both children on cgroup v2 and targets child policy writes by descriptor, not pathname; it is **not** wired to launch or the reconciliation algorithm. [`openPinnedGroup`](../../internal/resourcegroups/pinned_linux.go#L42-L67) checks cgroup-v2 magic, but the fake test [`TestPinnedChildInterveningRenameRedirectsDescriptor`](../../internal/resourcegroups/authority_linux_test.go#L691-L735) runs on an **ordinary temporary directory**. It demonstrates a generic-filesystem fd/name race, not a cgroup-v2 rename.

**Read from source, 2026-11-05:** upstream Linux [`kernel/cgroup/cgroup.c`, `cgroup_on_dfl` comment](https://github.com/torvalds/linux/blob/master/kernel/cgroup/cgroup.c#L309-L326) explicitly describes the v2/default hierarchy and says `rename(2) is disallowed`. The [kernel cgroup-v2 guide, Basic Operations](https://docs.kernel.org/admin-guide/cgroup-v2.html#basic-operations) says a group with no child and no live process can be removed via `rmdir`, and another may then be created at the same pathname. Thus *rename-to-sibling* is the wrong native counterexample, but **delete/recreate and owner policy revocation remain real**. Verify the applicable host kernel and mount before relying on this property; the cited current upstream is not a native witness.

**Inference, not yet demonstrated:** on an actually verified cgroup-v2 mount, opening the assigned group and each child with no symlink traversal, then performing child policy I/O only relative to the pinned **child descriptor**, can prevent a deletion/recreation from redirecting that write into the newly named replacement (or an unrelated sibling): a descriptor identifies the old object, which may reject writes after removal. A pathname write after a pre-write identity comparison cannot make this claim. A descriptor alone does **not** establish that the old group is still live, still selected by the manager, or where work will run. Post-write manager/path/inode/policy and actual PID-membership witnesses must reject a changed identity **before required work**, while acknowledging owner changes immediately after the last observation can revoke enforcement. Neither `flock` nor re-observation excludes a non-cooperating same-UID owner.

## Conditional least-authority route to test, not to activate

1. **Existing user-manager scope/service with a proven delegated subtree**, already authorized for the selected workload, is the possible anchor. [systemd's delegation description](https://systemd.io/CGROUP_DELEGATION/) says the unit's own attributes remain manager-owned; below a `Delegate=` scope/service systemd ordinarily leaves child management to the delegatee, but may itself create a manager-owned **`.control/`** subgroup for control processes. A **slice name is not delegation**; do not write below a systemd-owned slice or the owner-managed parent, touch `.control/`, or assume either Yolo child name is ours without checking its identity and ownership. [`Delegate=` reference](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html#Delegate=) says controller delegation may only be a request, not proof of usable `io`. The same [reference](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html#DelegateSubgroup=) distinguishes manager-placed main processes from control processes. An active delegated scope/service for the required lifetime, cgroup-v2 mount, selected user-manager identity, writable owned subtree, `io` available and enabled, and assigned finite device budget are **all** prerequisites. The existing read-only [`ResolveSelectedIOPaths`](../../internal/resourcegroups/resolve.go#L17-L58) identifies a `ControlGroup` and `io.max` but does not prove `Delegate=`, lifetime, child ownership, or write rights.
2. **Yolo-created `yolo-agent`/`yolo-batch` only below that verified delegated anchor**, serialized among Yolo launchers by the existing assigned-group private lock. Pin anchor/children through `openat` and cgroup-v2 `fstatfs`; resolve and reread the manager-selected identity, controller, ancestor and parent finite bounds; write **only child** `io.max` via checked pinned child descriptors, never via a previously checked pathname. Do not enable parent controllers by writing owner policy or assume path access is authority. Verify both child identities and exact readback plus fresh parent and ancestor state; abort on unlink/recreate, stale values, missing controller, timeout or owner change, retain uncertain live children. [Kernel controller rules](https://docs.kernel.org/admin-guide/cgroup-v2.html#controlling-controllers) require availability in `cgroup.controllers` and explicit `cgroup.subtree_control` enablement; reject instead of changing an unowned ancestor. Finite shared group-pair arithmetic remains as in the existing fake implementation, not separate caps per session.
3. **Before expensive start, prove the *actual* execution-boundary PID is already in the intended observed child** and that the selected unit/children and policies still match. A D-Bus `ControlGroup`, successful runtime argv or fake PID path alone proves no membership. This depends on a genuine pre-start placement mechanism and independent per-boundary evidence; not supplied by this research. [Kernel `cgroup.procs` and `/proc/$PID/cgroup` semantics](https://docs.kernel.org/admin-guide/cgroup-v2.html#basic-operations) support a membership observation but PID reuse and process moves require a live-process identity/lifetime witness. User-manager child rights cannot be inferred for system-manager mappings or this jail's cgroup namespace.

**Remaining authorization gap:** no inspected existing delegated unit with an I/O controller and a lifetime spanning the required shared children has been established. A transient unit is [released when no longer running/referenced or after reboot](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html); `ControlGroup` alone is neither a lease nor permission. The manager-controlled alternative — managing Yolo child *units* through the user manager rather than direct child cgroup writes — still needs proof of unit lifetime, caller's authority for *only* those children, observed I/O policy and membership; [`SetUnitProperties()`](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html) supports some runtime resource settings, not a promised compare-and-swap or replacement lock. Do not assume it closes this race.

**Boundary distinctions.** A same-UID owner legitimately can change a parent cap, move tasks, stop its unit or revoke delegation; this route must notice when it can and refuse new starts, not claim protection *against* the owner. An untrusted jail must never receive this host subtree, the host user bus, writable host cgroup paths, or extra grants. Concurrent Yolo writers can share a cooperative lock; other same-UID writers cannot be forced to cooperate. The kernel's non-renamability prevents the specific rename counterexample, but not owner revocation or lifecycle races. No privileged helper, new service, raw bind, expanded jail delegate, ACL/grant change, or owner policy rewrite is assumed.

## Falsifiable proof obligations and smallest next step

- **Implementation versus activation:** a bounded descriptor-relative Linux child-writer and pre-start guard may be built and fixture-tested **now**, behind the unchanged production refusal. Their static/fake checks do not authorize their activation. A rootless native authority/lifetime witness, independently reviewed writer and actual placement/PID proof are separate gates before activating any mapped writer or allowing required work.
- **Static/fixture TDD fence:** keep real `ReconcileUserIO` refusing. Test cgroup-v2-only admission and the real descriptor-relative syscall under a regular-filesystem fixture; replace a name after pinning and prove *no newly named replacement or sibling* is written, then fail the required start. Test child disappearance, owner-policy drift, missing delegation/lifetime, cancellation and wrong PID before wiring a real consumer. A generic-directory rename test remains useful for proving a pathname writer unsafe, not as native cgroup-v2 behavior. No test may use a fake native callback to claim real authority.
- **Minimum later READ-ONLY native witness (owner/host authority; request separately, not now):** on a suitable rootless Linux host, inspect the chosen unit's user/system manager identity, type, active state, `Delegate=`/controller list and `ControlGroup`; the mount's cgroup-v2 type and selected path; each ancestor `cgroup.controllers`/`cgroup.subtree_control`; assigned `io.max`, ownership/mode and absence/presence of both Yolo children (and any manager-owned `.control/`); and whether a safe manager-provided scope/service remains alive. This is *not* permission to create a unit, change policy, write `io.max`, or start jobs. Record observations without private paths or credentials. Rootful nested-jail status and Darwin compile cannot substitute for a rootless host witness.
- **Then review before activation:** if that witness shows no existing permitted delegated anchor, keep mappings unsupported. The smallest possible later unlock would be an **explicitly authorized, owner-provisioned delegated user scope/service with finite assigned policy and defined lifetime**, or independently validated manager-owned child units; either is a separate security/owner decision and setup, not an agent-side workaround. A witnessed suitable anchor alone does not establish real write or PID-placement authority. No public doc proves the local host meets those conditions.

**Disposition:** native cgroup-v2 non-renamability falsifies the prior *rename* justification for unconditional refusal; it does **not** authorize deleting the refusal today. Ready for independent review of the unactivated prototype and a separately approved read-only native witness, **not** ready for production writer activation, placement, or enforcement claim. This separates the [engineering gates](../design/resource-groups.md#engineering-gates-for-enforcement-and-performance-claims) from the accepted algorithm and preserves the fail-closed selected launch.
