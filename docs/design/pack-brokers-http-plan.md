## Reuse and traps

- **Reuse:** `loopholedecl.Decode`/`LoadDir`, `parseCallBroker`, `config.validateBrokeredWorkspace`, `run.selectedCallBrokerLaunchInput`, `callbrokerinput.Launch` and `DeclarationHash` compose strict selected declaration → gate → private launch. `brokerstore.Store` and `approvalwait.Record` have distinct host versus published state; reuse exact filing/spend APIs, not a new approval RPC. `hostservice.handleOne` receives the host-asserted jail identity from a preamble. `callbroker.Classifier.invoke` enforces one JSON stdin, a 64 KiB answer and two seconds.
- **Trap:** selected defaults or `EnvFromHost` presence are not approved HTTP binding. Freeze the exact name/origin/header/source/prefix; recheck current selection, ceiling, grant and lease at dispatch. Neither jail nor classifier receives credentials. CLI `OriginalArgv` replay remains unchanged.
- **Trap:** bound only authenticated HTTP ingress before reading its body; generic `frameproto.ReadRequestBytes` allocates using a uint32 length and Git/GH/CLI must not inherit a new frame cap. A classifier-unit test cannot prove selected-front host effects.
- **Trap:** a disconnected fixture seeing zero requests cannot prove redirect protection; a first counted receiver must send a redirect to a second counted listener. Known-token redaction does not promise encoded or transformed-secret protection.

- **HTTP ingress:** `hostservice.handleOne` uses `frameproto.ReadRequestBytes`, which trusts a uint32 length before allocation. Bound the authenticated HTTP ingress **before** allocating; do not impose a new cap on other Git/GH/CLI request readers. `callbroker.Classifier.invoke` currently marshals one CLI JSON input, checks 64 KiB, then reads a 64 KiB answer; HTTP requires a separate 4,456,448-byte JSON input budget while keeping one JSON stdin, 64 KiB answer and 2 s deadline. An unbound classifier-only test does not establish HTTP execution.
- **Binding trap:** `loopholedecl.parseCallBroker` currently permits `front=http` but lacks an `http` declaration; its lookup fields are only method/path. `callbrokerinput.Launch` and `run.selectedCallBrokerLaunchInput` omit HTTP binding; `callbroker.Main` constructs only `newCLIHandler`, `ApprovalAuthority` requires CLI, and the newly integrated `cmd/yolo-jaild/main.go` front dispatch remains manually reachable but has no selected producer, readiness or publication path. The fixture/G tests must go through these production call sites. F's host-env source repair is CLI-scoped: HTTP `host_env` needs the **exact approved variable name** plus origin/source/header/prefix gate binding, not merely `EnvFromHost` presence. `fenced_file` is inside approved credential paths with current host-user owner, nonsymlink regular 0600, <=8 KiB and no empty/control value.
- **Custody trap:** `brokerstore.Request.OriginalArgv` and `ApprovalAuthority` replay the CLI classifier from stored argv/digest; HTTP must persist only nonsecret intent/digests/cells/native IDs/metadata, never original/canonical body or a replayable request, and reclassify the resubmitted original body at act. Preserve CLI storage and digest semantics. Native parents need fresh exact-read lookups, not stored chains or a fixture oracle; read standing is tested on **every** lookup and at act.

## Common gates and hand-off protocol

One commit per ordered G1 → G2 → G3 → G4 → H task, after the source prerequisite. On a clean tree write the consumer regression first and run its exact red command; missing symbols alone are not behavioral red. After green run task package gates and `just format`. For `internal/`/`cmd/` changes run `just build-dev-bundle` and its emitted absolute launcher from a throwaway workspace. The landing owner runs combined `just check-ci`, relevant integration, and one full slow suite; a nested rootful jail cannot prove rootless reachability or macOS behavior. If a test reads outside its package run `python3 scripts/completion-census.py` and commit its output. Report red/green commands, counted host effects, audit/spend and unsupported backends. Stop on unexpected drift; do not diagnose an unapproved behavior into code.

#### Where the source changed the sketch

The sketch above assumed things the tree does not support. Each is ruled here, inside the design's boundary, so no new open question is filed.

1. **No host-held address exists to hand over.** Launcher reservations (`servedaddresses.go`, `launchservice.ReservePorts`) are released before the container starts, nothing is reserved on a private network namespace, and no descriptor crosses into a container. Ruling: the front binds `127.0.0.1:0` itself and fails closed if that bind fails. There is no declared port, no `front_listen` key and no declared-address fallback; `servedaddresses.go` and `loopholedecl.ListenAddressProblem` stay untouched. The address is reported, not trusted: the pinned per-front certificate is the identity, so a process that later squats a freed port cannot complete TLS against the published trust.
2. **The front mints its own key in memory**, following `svcendpoint`'s rule that a private key never leaves process memory (the unexported `mintCert` in `internal/svcendpoint/cert.go`). Only the certificate goes to the host. No key file exists anywhere, which is stronger than the design text's "certificate/key in a private per-generation payload". Aligning that design sentence is a follow-up for the design's owner, not this plan.
3. **The keeper cannot produce the receipt the sketch named.** It sees only `entrypoint.BootReadyLine` and cannot reach the jail's loopback. Ruling: the front seals itself through one side-effect-free host op, `seal`, over the host endpoint it already uses. That connection's preamble asserts the jail identity, and another jail cannot read this jail's `/run/yolo-services`, so this stays within the stated caller boundary.
4. **The front never holds the raw token.** The host mints it with `svcendpoint.NewToken` at seal time and keeps it in a host-private file. The front receives only its SHA-256 and compares hashes with `crypto/subtle.ConstantTimeCompare`.
5. **Today's front forwards the caller's `Authorization` into the host frame** (`frontHeaders` copies every header, and `digestHTTPCall` digests the original headers). The front must strip the local credential field before building `HTTPCall`, and the host also refuses any frame carrying the sealed token bytes, before classification.
6. **The `401` is new.** Every refusal in `httpfront.go` is a `403` through `writeRequestRefusal`, and `ServeHTTP` reads the body before calling the host. Authentication becomes the first check.
7. **No production producer starts the front**: `call-broker-http-front` appears only in `cmd/yolo-jaild/main.go`, its test and `httpfront.go`. Slice 3.4 adds the first.

#### Decisions (cheap, recorded so nobody re-derives them)

- **Restart policy `no` for the front.** A broker restart gets a new start ID, so the seal is stale and ordinary frames refuse with "stop the jail and relaunch".
- **Legacy G3 inputs** (no `HTTPFrontGeneration`) keep accepting frames without `front_generation`, and refuse a frame that carries one and the `seal` op. Existing host tests stay valid.
- **Seal and token leaves** sit beside the prepared record: `<launch-input>.prepared.seal` and `<launch-input>.prepared.token`, both `0600`, created with `O_EXCL|O_NOFOLLOW`. The token file holds exactly the 64 hex characters, no newline. Write the token first, then the seal; if the seal write fails, remove the token. A leftover token without a seal refuses a later seal ("relaunch"), which fails closed.
- **The local credential field** is the binding's own `HTTPBinding.HTTP.Credential.Header` and `Prefix` (for example `Authorization` and `Bearer `): the client sends the local token where it would send its usual credential.
- **The daemon name** is `http-front-<loophole>`, and readiness uses the existing line protocol: `ready <name>` after a successful seal, `failed <name> <reason>` otherwise. Copy the dup-and-write shape of `signalReadinessOnFD` in `internal/wirebridged/boot.go` as a private helper; do not export `launchservice.reportReadiness`.
- **Response shapes:** the `401` reuses the existing GraphQL `errors` body with `Yolo-Verdict: refused`. The token found anywhere other than the designated field gets a local `403` with handler zero. Duplicate or conflicting designated fields get a `401`. `Yolo-Authorization-Stripped` stays, set only when a non-designated authorization header was stripped.
- **Map types, helper factoring and error wording** beyond the strings quoted below are the builder's choice.
- **Seal decoding (3.1, as built):** `rejectDuplicateObjectKeys` in `privateclient.go` is hard-wired to the prepared record's own key set, so it would refuse every seal key. Rather than widen a fenced file, `frontseal.go` carries a flat strict scanner with the same refusals: exact keys only (a case-folded alias or duplicate is an unknown key), no duplicate, every value a string, no trailing JSON.
- **Handler state (3.1, as built):** `HTTPHandler` already reaches `inputFile` through its embedded `CLIHandler`, so only the in-memory `front` state is new. Seal routing (`handleSeal`) lives in `http_seal.go`. The token gate checks the compact frame and the decoded body bytes, since a base64 body would hide the token from a frame-only search.
- **Seal validation (3.1 fix-forward):** `PreparedHTTPFrontSeal.Validate` checks more than the schema. It also requires the pinned certificate to parse, to name the sealed address as an IP SAN, and to allow `ServerAuth`, through `callbrokerinput.CheckHTTPFrontCertificate`. The host's `seal` calls the same function. A reader that trusts `DecodePreparedHTTPFrontSeal` alone, such as Task 4's publisher, therefore gets a self-consistent seal. `HTTPHandler.beforeSealWrite` is a test-only seam, nil in production, placed between the token and seal leaf writes so the token removal on a failed seal write is pinned.
- **Front startup (3.2, as built):** `ServeHTTPFront(ctx, endpoint, loophole, generation)` wraps an unexported `serveHTTPFront` that also takes the request timeout, so tests can bound a stalled body without a wall-clock pass condition. The front writes the readiness line itself, with a private copy of `wirebridged`'s `signalReadinessOnFD` pattern (dup the descriptor, one flattened line), rather than importing that package. A missing generation, any repeat of the loophole's key in `YOLO_HTTP_FRONT_GENERATIONS` (an empty first entry included), an invalid argument to `ServeHTTPFront` that still names a loophole, and any bind, mint or seal error before ready, write `failed http-front-<loophole> <reason>`. A flag error exits `2` and writes nothing, since it may not name a loophole. The seal exchange has its own fixed deadline (`httpFrontSealTimeout`, 30 seconds), independent of the per-request timeout. The certificate mirrors `svcendpoint`'s `mintCert`: `IsCA` for non-Go verifiers, `NotBefore` backdated an hour, a ten-year lifetime for a key that never leaves the process.
- **Token outside its field (3.2, as built):** after authentication, the front refuses locally with the host's `errFrontTokenOutsideSlot` message when the token appears in the escaped or decoded path, the raw query or any query name or value decoded on its own, `Host`, any other header name or value, or the body. Decoding is lenient: a well-formed `%XX` is decoded and a malformed one is kept literally, so one bad escape cannot hide an encoded token elsewhere in the request. The host's own gate from 3.1 still runs behind it.
