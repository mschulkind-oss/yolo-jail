### 1. W-SU13: Seatbelt workspaces from before 6a-iii relaunch

Before the launches, `ls /Users/Shared/yolo-staged/inherited-delivered | grep -E 'su12-d|w7-move'`
listed only the old-name records `yolo-su12-d-fe3a8973.json` and `yolo-w7-move-0e9df7a2.json`.

`yolo --setup seatbelt-self -- true` in `su12-d` and `yolo --setup seatbelt-yolo-account -- true`
in `w7-move` each exited 0, and neither printed the "is in the way" refusal. Afterwards the same
`ls` listed both names for each workspace:

```text
yolo-su12-d-fe3a8973-seatbelt-self.json
yolo-su12-d-fe3a8973.json
yolo-w7-move-0e9df7a2-seatbelt-yolo-account.json
yolo-w7-move-0e9df7a2.json
```

So the fix writes a record under the new jail name and leaves the old-name record in place.

Both copies of the user config kept their first line, `# GENERATED by yolo at jail launch — do not
edit; your edits are`, and their earlier modification times. The launch did not rewrite them:

```text
-r--r--r--@ 1 matt       _yolojail  - 4646 Nov  9 16:09 …/su12-d/.yolo/setups/seatbelt-self/home/.config/yolo-jail/config.toml
-r--r--r--@ 1 _yolojail  _yolojail  - 4646 Nov  6 22:56 …/w7-move/.yolo/setups/seatbelt-yolo-account/home/.config/yolo-jail/config.toml
```

Each also carried two inherited ACL entries allowing read, write and delete: one for
`group:_yolojail` and one for an account ID.

**The negative case.** In `su12-d`, I appended `# edited` to that `config.toml` (`chmod u+w`, then
`chmod 0444` again) and launched again. It exited 1 with *"refusing macos-user inherited preflight
scope: existing user file …/su12-d/.yolo/setups/seatbelt-self/home/.config/yolo-jail/config.toml
is in the way, and the home-overlay installer cannot prove it is a file it delivered before, …
move it aside (mv … …config.toml.moved-aside) and relaunch"*. Afterwards I removed the added line,
which restored the staged bytes.

### 2. W-SU1's launch half in w7-move

`w7-move`'s `seatbelt-yolo-account` state predates 6a-iii, and its `seatbelt-self` launch was its
first. Both shells ran, started in the background with `-- bash -c 'echo HOME=$HOME; echo
USER=$(id -un); sleep 900'`:

- `seatbelt-self`: `HOME=/Users/Shared/yolo/w7-move/.yolo/setups/seatbelt-self/home`, `USER=matt`.
- `seatbelt-yolo-account`: `HOME=/Users/Shared/yolo/w7-move/.yolo/setups/seatbelt-yolo-account/home`,
  `USER=_yolojail`.

`yolo setup list` marked both `built-in, running`. `yolo stop` printed `stopped seatbelt-self` and
`stopped seatbelt-yolo-account`, each after its keeper teardown. It printed **no "No jail running"
line** this time, so that half of item 2 is fixed. Both shells ended with 143.
`env | grep YOLO_RUNTIME` printed nothing.

### 3. W-SU12 from the start

These were fresh workspaces, `/Users/Shared/yolo/su12r-c` and `/Users/Shared/yolo/su12r-d`
(`git init`, no config). In each, the `bb10db358` yolo started a long-running shell. Then the new
yolo's `-- true` launch exited 1, and `ls .yolo/setups` was the same before and after:

- **Apple Container:** *"Refusing to launch: a jail an earlier yolo started for this workspace
  (yolo-su12r-c-9a9f8f00) is still running. … Stop it, then launch again: `yolo stop` from this
  workspace, or `container stop yolo-su12r-c-9a9f8f00`."* This fixes the other half of item 2.
- **Seatbelt:** the same refusal for `yolo-su12r-d-63b292fa`, ending *"`yolo stop` from this
  workspace."* alone, as expected.

`yolo stop` printed *"Stopping the jail an earlier yolo started for this workspace (…)"* in both.
The Seatbelt one added *"This workspace's jail was launched on macos-user, so this stop asks
macos-user, not container."* Neither printed a "No jail running" line, and each old shell ended
with 143. Both relaunches then exited 0. The Apple Container launch log names the jail
`yolo-su12r-c-9a9f8f00-apple-container-self`.

**Prune.** `yolo prune` (a dry run, stdin closed) listed *"Apple Container tool disks … none"*, and
`container volume ls` still shows both `yolo-su12r-c-9a9f8f00-apple-container-self.mise` and the
old jail's `yolo-su12r-c-9a9f8f00.mise`.
